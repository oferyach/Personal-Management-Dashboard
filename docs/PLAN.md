## 0. How we will work (phase-gate protocol)

Every phase ends at a hard gate. Nothing moves to the next phase without your approval.

```
implement phase → run gate (lint + typecheck + unit + integration + e2e + prod build)
                → write "Phase N verification report" into PROGRESS.md
                  (commands run, actual results, gaps, what is NOT verified)
                → STOP and wait for your approval
                → only then start Phase N+1
```

Rules I will follow:

1. `README.md` (the spec) is **never overwritten**. At Phase 6 the project README is added as `README.md` **only after** the spec is copied verbatim to `docs/PROJECT-SPEC.md` and you approve the swap. Until then all my docs live in `docs/` and `PROGRESS.md`.
2. A feature counts as done only if it is wired to the database and exercised by an executed test — no placeholder pages, no fake buttons, no mock dashboards.
3. If an external service can't be exercised (no OneDrive/SMTP credentials), the implementation is completed, mocked in tests, and the unverified part is written down explicitly.
4. Each commit-sized work item has an ID (e.g. `3.4`); `PROGRESS.md` tracks them individually.
5. If a gate test fails, I fix it and re-run — I do not report success on a failed gate.

## 3. Cross-cutting foundations (built in Phase 1, used by all later phases)

Built once, tested once, never re-implemented per feature:

- `lib/env.ts` — Zod-validated env (`NODE_ENV`, `DATABASE_URL`, `APP_URL`, `SESSION_SECRET`, `APP_ENCRYPTION_KEY`, SMTP block, Graph block, TZ default). App refuses to boot in production with missing/weak secrets.
- `db/client.ts` — better-sqlite3 with `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`, `synchronous=NORMAL`, WAL/checkpoint hygiene.
- `server/rbac` — `roles`, `permissions`, `role_permissions`, `resource_permissions`, `requirePermission()` server-side guard + `canView/canEdit(actingUser, resource)`. Every service method takes an explicit actor; ownership enforced in queries, not UI.
- `server/audit` — append-only audit log (actor, action, target, outcome, ip hash, timestamp), never secrets.
- `lib/crypto` — AES-256-GCM `encryptSecret/decryptSecret` + versioned key id; Argon2id wrappers.
- `server/jobs` — `enqueue(type, payload, runAt, dedupeKey)`, claim with `BEGIN IMMEDIATE` + lease (`locked_by`, `lease_expires_at`), attempts/backoff, `job_runs` history, stale-lease reclaim on startup, per-type concurrency limits.
- `server/activity` — typed activity events consumed by the activity feed and dashboard.
- `components/ui` — sidebar/nav shell, light+dark theme, toasts, confirm dialogs, empty/loading/error states, pagination/virtualized lists, keyboard nav, focus management.
- `lib/i18n` + RTL-ready layout primitives; user `language`/`timezone`/`theme` preference plumbing. **Hebrew is the primary language (amendment A-2): the `he` dictionary is the key-shape source of truth, `en` is typed against it, and `dir` is resolved server-side before the first byte of HTML.**
